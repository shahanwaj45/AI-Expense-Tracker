SECTION 1 — HOW FRONTEND CONNECTS TO BACKEND
════════════════════════════════════════════════════════════════════════════════

  [Browser / React App]  ──── HTTP REST API calls ────►  [Flask Server]
  http://localhost:3000                                   http://localhost:5000

  Every time the React frontend needs data (e.g., load dashboard, add expense,
  get AI insight), it sends an HTTP request to the Flask backend.

  Connection Flow:
  ─────────────────
  1. User opens http://localhost:3000 in browser
  2. React app loads (Vite serves the HTML/JS/CSS)
  3. On login, React sends POST to http://localhost:5000/api/auth/login
  4. Flask returns a JWT (JSON Web Token) — a secure identity key
  5. React stores this token in memory / localStorage
  6. Every next request sends this token in the Header:
       Authorization: Bearer <jwt_token>
  7. Flask verifies the token and returns the requested data as JSON
  8. React displays the data to the user

  CORS (Cross-Origin Resource Sharing):
  ─────────────────────────────────────
  Since React runs on port 3000 and Flask on port 5000, the browser would
  normally block the request (different origins). Flask-CORS is configured to
  explicitly ALLOW requests from:
    - http://localhost:3000
    - http://127.0.0.1:3000
    - http://localhost:5173

SECTION 5 — AUTHENTICATION FLOW (JWT)
════════════════════════════════════════════════════════════════════════════════

  Step 1: User registers or logs in
          POST /api/auth/login
          Body: { "email": "...", "password": "..." }

  Step 2: Server validates credentials and returns:
          { "data": { "token": "eyJhbGci...", "user": { ... } } }

  Step 3: Frontend stores the token

  Step 4: Every protected request includes:
          Header: Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5...

  Step 5: Flask decodes the token using Flask-JWT-Extended
          → Extracts user ID and role from token payload
          → If token is valid: returns requested data
          → If token is invalid/expired: returns 401 Unauthorized

  Token Expiry: 7 days (configured in config.py)
  Algorithm:    HS256 (HMAC-SHA256)

SECTION 6 — AI & ML FEATURES
════════════════════════════════════════════════════════════════════════════════

  A) AI INSIGHTS (Google Gemini 1.5 Flash)
  ──────────────────────────────────────────
  How it works:
  1. Backend collects user's financial summary:
     - Total spent this month
     - Top spending category
     - Monthly budget vs actual spending
     - Average savings goal progress (%)
  2. Sends this as a prompt to Google Gemini API
  3. Gemini returns a personalized financial tip as JSON
  4. Response is stored in ai_insights table (cached)
  5. Displayed on the Insights page in the app

  Fallback: If GEMINI_API_KEY is not set, a random pre-written insight is shown.

  B) VOICE EXPENSE PARSING (Gemini)
  ──────────────────────────────────────────
  User speaks: "I spent 250 rupees on lunch today"
  Backend sends this text to Gemini →
  Gemini returns: { "name": "Lunch", "amount": 250, "category": "Food" }
  This is automatically filled into the add-expense form.

  C) RECEIPT OCR (Google Cloud Vision)
  ──────────────────────────────────────────
  User uploads a photo of a bill/receipt →
  Google Cloud Vision reads the text →
  Amount and merchant name are extracted →
  Auto-fills the expense form.

  D) ML SPENDING PREDICTION (scikit-learn)
  ──────────────────────────────────────────
  Analyzes past transaction history →
  Predicts likely spending for next month per category →
  Shown on the Predictions / Analytics page.
